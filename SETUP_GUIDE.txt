STEP 1: INSTALL POSTGRESQL & REDIS (LOCAL DEVELOPMENT)
================================================================================

OPTION A: Using Docker (Easiest - Recommended)
-----------------------------------------------
If you have Docker installed, this is the simplest way:

1. Make sure Docker Desktop is running

2. Use the provided docker-compose.yml:
   cd /Users/shivamkumarsingh/Documents/zyloshipping/zyloshipping
   docker-compose up -d postgres redis
   
   This starts:
   - PostgreSQL on port 5432
   - Redis on port 6379

3. Verify they're running:
   docker ps
   
   Should show both containers running

4. Your connection strings will be:
   DATABASE_URL="postgresql://zyloshipping:zyloshipping_dev_password@localhost:5432/zyloshipping?schema=public"
   REDIS_URL="redis://localhost:6379"

5. To stop them later:
   docker-compose down

6. To view logs:
   docker-compose logs postgres
   docker-compose logs redis

OPTION B: Install PostgreSQL Locally (macOS)
---------------------------------------------
1. Install PostgreSQL using Homebrew:
   brew install postgresql@16

2. Start PostgreSQL service:
   brew services start postgresql@16

3. Create database and user:
   # Connect to PostgreSQL
   psql postgres
   
   # In psql prompt, run:
   CREATE DATABASE zyloshipping;
   CREATE USER zyloshipping WITH PASSWORD 'your_password';
   GRANT ALL PRIVILEGES ON DATABASE zyloshipping TO zyloshipping;
   \q

4. Your connection string:
   DATABASE_URL="postgresql://zyloshipping:your_password@localhost:5432/zyloshipping?schema=public"

5. To stop PostgreSQL:
   brew services stop postgresql@16

6. To check if running:
   brew services list

OPTION C: Install Redis Locally (macOS)
----------------------------------------
1. Install Redis using Homebrew:
   brew install redis

2. Start Redis service:
   brew services start redis

3. Verify Redis is running:
   redis-cli ping
   # Should return: PONG

4. Your connection string:
   REDIS_URL="redis://localhost:6379"

5. To stop Redis:
   brew services stop redis

6. To check Redis data:
   redis-cli
   # In redis-cli:
   KEYS *
   GET some_key
   exit

OPTION D: Use Cloud Services (No Local Install)
------------------------------------------------
Skip local installation and use cloud services:

PostgreSQL - Supabase (Free):
1. Go to https://supabase.com
2. Create account and new project
3. Wait for database to provision (~2 minutes)
4. Go to Settings > Database
5. Copy "Connection string" (URI format)
6. Replace [YOUR-PASSWORD] with your actual password
   Example: postgresql://postgres:your_password@db.xxx.supabase.co:5432/postgres

Redis - Upstash (Free):
1. Go to https://upstash.com
2. Create account
3. Create new Redis database
4. Copy the Redis URL
   Example: redis://default:your_password@xxx.upstash.io:6379

VERIFICATION:

   Error: "Cannot connect to Redis"
   - Check Redis is running: brew services list
   - Verify REDIS_URL in .env
   - Test: redis-cli ping
   
   Error: "Port 4000 already in use"
   - Kill existing process: lsof -ti:4000 | xargs kill -9
   - Or change PORT in .env
   
   Error: "Missing environment variable"
   - Check .env file exists in backend/
   - Verify all required variables are set
   - Compare with .env.example

   🚀 Server listening on port 4000

TERMINAL 2 - Start Frontend:

3. Start development server:
   npm run dev
   
4. Wait for startup (should see):
   ▲ Next.js 14.x.x
   - Local:        http://localhost:3000
   - Network:      http://192.168.x.x:3000
   ✓ Ready in 2.5s
   
5. If you see errors:
   
   Error: "Port 3000 already in use"
   - Kill existing process: lsof -ti:3000 | xargs kill -9
   - Or use different port: npm run dev -- -p 3001
   
   Error: "Module not found"
   - Reinstall dependencies: npm install
   - Clear cache: rm -rf .next && npm run dev
   
   Error: "Environment variable not found"
   - Check .env.local exists in frontend/
   - Verify NEXT_PUBLIC_BACKEND_URL is set

6. Frontend is ready when you see:
   ✓ Compiled successfully

METHOD 2: Docker Compose (Easiest - All-in-One)
------------------------------------------------
This starts PostgreSQL, Redis, Backend, and Frontend together:

1. Make sure Docker Desktop is running

2. Navigate to project root:
   cd /Users/shivamkumarsingh/Documents/zyloshipping/zyloshipping

3. Start all services:
   docker-compose up -d
   
   This starts:
   - PostgreSQL (port 5432)
   - Redis (port 6379)
   - Backend (port 4000)
   - Frontend (port 3000)

4. Check status:
   docker-compose ps
   
   All services should show "Up"

5. View logs:
   # All services
   docker-compose logs -f
   
   # Specific service
   docker-compose logs -f backend
   docker-compose logs -f frontend

6. Stop all services:
   docker-compose down
   
   # Stop and remove volumes (clean slate)
   docker-compose down -v

7. Restart a service:
   docker-compose restart backend
   docker-compose restart frontend

METHOD 3: Background Processes (Advanced)
------------------------------------------
Run backend and frontend in background:

1. Start backend in background:
   cd backend
   nohup npm run dev > backend.log 2>&1 &
   echo $! > backend.pid

2. Start frontend in background:
   cd ../frontend
   nohup npm run dev > frontend.log 2>&1 &
   echo $! > frontend.pid

3. View logs:
   tail -f backend/backend.log
   tail -f frontend/frontend.log

4. Stop processes:
   kill $(cat backend/backend.pid)
   kill $(cat frontend/frontend.pid)

COMMON STARTUP ISSUES:
----------------------

Issue: Backend won't start
Solutions:
- Check .env file exists and has all required variables
- Verify PostgreSQL and Redis are running
- Check port 4000 is not in use: lsof -i:4000
- Review error messages in terminal
- Try: rm -rf node_modules && npm install

Issue: Frontend won't start
Solutions:
- Check .env.local exists
- Verify NEXT_PUBLIC_BACKEND_URL is set
- Check port 3000 is not in use: lsof -i:3000
- Clear Next.js cache: rm -rf .next
- Try: rm -rf node_modules && npm install

Issue: "Cannot connect to backend" in browser
Solutions:
- Verify backend is running: curl http://localhost:4000/health
- Check NEXT_PUBLIC_BACKEND_URL in .env.local
- Check browser console for CORS errors
- Verify FRONTEND_URL in backend .env

Issue: Database connection errors
Solutions:
- Verify PostgreSQL is running
- Check DATABASE_URL format
- Test connection: psql $DATABASE_URL
- Run migrations: npx prisma db push

Issue: Redis connection errors
Solutions:
- Verify Redis is running
- Check REDIS_URL format
- Test connection: redis-cli ping
- Restart Redis: brew services restart redis

Issue: "Cannot connect to database"

- Clear browser cache

Issue: "Payment webhook not working"
Solution:
- Verify webhook URL in payment gateway dashboard
- Check webhook secret matches .env
- Test webhook with gateway's test tool
- Check backend logs for webhook errors

Issue: "Products not syncing"
Solution:
- Verify supplier API keys in .env
- Check supplier API status
- Manually trigger: POST /api/admin/products/sync
- Check backend logs for errors

Issue: "AI agents not running"
Solution:
- Verify GROQ_API_KEY in .env
- Check Groq API quota (14,400/day free)
- Add OPENAI_API_KEY as fallback
- Check agent status in admin dashboard

Issue: "Email not sending"
Solution:
- Verify RESEND_API_KEY
- Check Resend dashboard for errors
- Verify sender domain configured
- Check email quota (100/day free tier)

Issue: "Build fails on Vercel"
Solution:
- Check build logs for errors
- Verify all dependencies in package.json
- Check TypeScript errors: npm run type-check
- Verify environment variables set

Issue: "Database migration failed"
Solution:
- Check DATABASE_URL has direct connection (not pooler)
- Use DIRECT_URL for migrations
- Run: npx prisma migrate reset (WARNING: deletes data)
- Or: npx prisma db push --force-reset
