1. PROJECT OVERVIEW
================================================================================

ZyloShipping is a production-ready dropshipping e-commerce platform that 
connects customers with products from multiple suppliers (AliExpress, CJ 
Dropshipping). The platform handles the entire order lifecycle from browsing 
to delivery, with AI-powered automation for pricing, content generation, and 
customer support.

KEY CAPABILITIES:
- Multi-supplier product catalog with automatic sync
- Real-time inventory management
- Multiple payment gateways (Razorpay, Stripe, UPI)
- AI-powered product curation and pricing
- Automated order routing to suppliers
- Real-time shipment tracking via AfterShip
- Admin dashboard with analytics
- Customer cart and order management
- Email notifications for all order events

BUSINESS MODEL:
1. Products are sourced from suppliers (AliExpress, CJ Dropshipping)
2. Platform applies markup (default 2.5x) to supplier cost
3. Customer pays platform price
4. Platform orders from supplier at cost price
5. Profit = Customer Price - Supplier Cost - Platform Fees

- Search: Algolia
- Email: Resend

- Tracking: AfterShip
- AI: Groq (primary), OpenAI (fallback)

FRONTEND STACK:
- Framework: Next.js 14 (App Router)
- Language: TypeScript
- Styling: Tailwind CSS
- State Management: Zustand
- Forms: react-hook-form + Zod
- Icons: Lucide React
- Animations: Framer Motion
- Notifications: Sonner
- Payments: Stripe Elements, Razorpay SDK

INFRASTRUCTURE:
- Containerization: Docker (multi-stage builds)
- Frontend Hosting: Vercel
- Backend Hosting: Railway/Render/DigitalOcean
- Database: Supabase/Railway PostgreSQL
- Cache: Upstash Redis or self-hosted
- CDN: Vercel Edge Network

TABLES & RELATIONSHIPS:

User
----
- id: String (UUID)
- email: String (unique)

- phone: String?

- id: String (UUID)
- sku: String (unique)
- slug: String (unique)
- title: String
- description: String?

- price: Float

- stockQuantity: Int
- status: ProductStatus (ACTIVE, HIDDEN, LOW, DRAFT, ARCHIVED)

- imagesJson: Json (array of image URLs)
- rating: Float
- totalSales: Int
- createdAt: DateTime
- updatedAt: DateTime

- supplier: Supplier

AiLog
-----
- id: String (UUID)

- latencyMs: Int

AdminLog
--------
- id: String (UUID)
- userId: String
- action: String

Relations:

ProductMetricAudit
------------------
- id: String (UUID)
- productId: String

Relations:
- product: Product

INDEXES:
- User: email (unique)

POST   /api/auth/register

       Body: { email, password }
       Returns: { user, accessToken, refreshToken }
       Sets: HTTP-only cookies with tokens
       
POST   /api/auth/refresh
       Headers: Cookie with refreshToken
       Returns: { accessToken }
       
POST   /api/auth/logout
       Clears: Authentication cookies
       Returns: { message: "Logged out" }
       
GET    /api/auth/me
       Headers: Authorization: Bearer {accessToken}
       Returns: { user }
       
POST   /api/auth/forgot-password
       Body: { email }

POST   /api/auth/reset-password

       Returns: { message: "Password reset" }

7. AUTHENTICATION & AUTHORIZATION
================================================================================

AUTHENTICATION FLOW:
1. User registers or logs in
2. Server generates JWT access token (15min expiry)
3. Server generates JWT refresh token (7 days expiry)
4. Tokens stored in HTTP-only cookies
5. Frontend includes token in Authorization header
6. Server validates token on protected routes
7. Token refresh when access token expires

JWT PAYLOAD:
{
  userId: string,
  email: string,
  role: "CUSTOMER" | "ADMIN",
  iat: number,
  exp: number
}

AUTHORIZATION LEVELS:
- Public: No authentication required
- Authenticated: Valid JWT token required
- Admin: JWT token + ADMIN role required
- Admin + MFA: JWT token + ADMIN role + TOTP verification

MIDDLEWARE CHAIN:
1. authMiddleware - Verifies JWT token
2. requireAdmin - Checks ADMIN role
3. requireMFA - Verifies TOTP code (for sensitive operations)

PASSWORD SECURITY:
- Hashed with bcrypt (12 rounds)
- Minimum 8 characters
- Must contain uppercase, lowercase, number, special char
- Password reset via email token (1 hour expiry)

MULTI-FACTOR AUTHENTICATION (MFA):
- TOTP (Time-based One-Time Password)
- QR code generation for authenticator apps
- Backup codes for recovery
- Required for admin sensitive operations

8. PAYMENT PROCESSING
================================================================================

SUPPORTED PAYMENT METHODS:
1. Razorpay (India)
   - Credit/Debit Cards
   - UPI
   - Net Banking
   - Wallets (Paytm, PhonePe, etc.)
   
2. Stripe (International)
   - Credit/Debit Cards
   - Apple Pay
   - Google Pay
   
3. UPI Direct
   - UPI VPA
   - QR Code

PAYMENT FLOW:
1. Customer adds items to cart
2. Proceeds to checkout
3. Selects payment method
4. Frontend creates payment intent via API
5. Payment gateway processes payment
6. Webhook confirms payment
7. Order status updated to PROCESSING
8. Order sent to supplier
9. Confirmation email sent

RAZORPAY INTEGRATION:
- Create order: POST /api/payments/razorpay/create-order
- Frontend displays Razorpay checkout
- Customer completes payment
- Razorpay sends payment_id, order_id, signature
- Backend verifies signature
- Order confirmed

STRIPE INTEGRATION:
- Create payment intent: POST /api/payments/stripe/create-payment-intent
- Frontend uses Stripe Elements
- Customer enters card details
- Stripe processes payment
- Webhook confirms payment
- Order confirmed

UPI FLOW:
- Initiate UPI: POST /api/payments/upi/initiate
- Generate QR code or collect VPA
- Customer approves on UPI app
- Poll for status: POST /api/payments/upi/verify
- Order confirmed on success

REFUND PROCESSING:
- Customer requests refund
- Admin reviews request
- Refund initiated via payment gateway API
- Refund status tracked
- Customer notified via email

9. AI AGENTS & AUTOMATION
================================================================================

AI PROVIDER:
- Primary: Groq (llama-3.3-70b-versatile)
  * Free tier: 14,400 requests/day
  * Fast inference (< 1s)
  * Cost-effective for production
  
- Fallback: OpenAI (GPT-4o)
  * Used when Groq fails
  * Higher quality for complex tasks
  * Pay-per-use pricing

AGENT ARCHITECTURE:
- Each agent is a separate module
- Agents run as BullMQ jobs
- State stored in AgentState table
- Logs stored in AiLog table
- Can be enabled/disabled via admin

CONTENT GENERATION AGENT:
Purpose: Generate product descriptions and marketing copy
Trigger: New product added or manual trigger
Process:
  1. Fetch product details
  2. Call LLM with product info
  3. Generate SEO-friendly description
  4. Update product in database
  5. Index in Algolia
Input: Product title, category, features
Output: Description, meta tags, keywords

PRODUCT CURATION AGENT:
Purpose: Analyze and recommend products from suppliers
Trigger: Daily cron job or manual trigger
Process:
  1. Fetch products from supplier APIs
  2. Analyze trends, demand, competition
  3. Score products based on criteria
  4. Recommend top products to admin
  5. Auto-add high-scoring products
Input: Supplier product catalog
Output: Product recommendations with scores

DYNAMIC PRICING AGENT:
Purpose: Optimize product pricing for maximum profit
Trigger: Hourly cron job
Process:
  1. Fetch competitor prices
  2. Analyze demand and conversion rates
  3. Calculate optimal price
  4. Update product prices
  5. Log price changes
Input: Product data, sales history, competitor prices
Output: Updated prices

ORDER ROUTING AGENT:
Purpose: Select best supplier for each order
Trigger: New order created
Process:
  1. Check product availability
  2. Compare supplier prices
  3. Estimate delivery times
  4. Calculate total cost
  5. Select optimal supplier
  6. Route order to supplier
Input: Order items, customer location
Output: Supplier assignment, estimated delivery

CUSTOMER SUPPORT AGENT:
Purpose: Answer customer questions automatically
Trigger: Customer message received
Process:
  1. Analyze customer query
  2. Check knowledge base
  3. Generate response
  4. Send to customer
  5. Escalate if needed
Input: Customer message, order history
Output: Response or escalation

REFUND & DISPUTES AGENT:
Purpose: Automate refund processing
Trigger: Refund request submitted
Process:
  1. Analyze refund request
  2. Check order status
  3. Verify eligibility
  4. Auto-approve simple cases
  5. Flag complex cases for review
Input: Refund request, order data
Output: Approval/rejection decision

REVIEW REPUTATION AGENT:

Trigger: New review submitted
Process:
  1. Analyze review sentiment
  2. Detect fake reviews

  4. Calculate product rating
  5. Update product score
Input: Review text, user history

11. TROUBLESHOOTING GUIDE
================================================================================

COMMON ISSUES & SOLUTIONS:

1. "Database connection failed"
   Cause: Invalid DATABASE_URL or database not accessible
   Solution:
   - Verify DATABASE_URL format
   - Check database is running
   - Verify network access
   - Test connection: psql $DATABASE_URL

2. "Redis connection failed"
   Cause: Invalid REDIS_URL or Redis not running
   Solution:
   - Verify REDIS_URL format
   - Check Redis is running
   - Test connection: redis-cli ping

3. "CORS error in browser"
   Cause: Frontend URL not in CORS whitelist
   Solution:
   - Add frontend URL to FRONTEND_URL env var
   - Check backend CORS configuration
   - Verify credentials: 'include' in fetch

4. "JWT token expired"
   Cause: Access token expired (15min)
   Solution:
   - Frontend should auto-refresh token
   - Check refresh token endpoint
   - Verify token expiry settings

5. "Payment verification failed"
   Cause: Invalid webhook signature
   Solution:
   - Verify webhook secret matches gateway
   - Check webhook endpoint URL
   - Test with gateway's test mode

6. "Products not syncing"
   Cause: Invalid supplier API keys
   Solution:
   - Verify API keys in .env
   - Check supplier API status
   - Review sync job logs
   - Manually trigger: POST /api/admin/products/sync

7. "AI agents not running"
   Cause: Missing GROQ_API_KEY or OpenAI key
   Solution:
   - Set GROQ_API_KEY in .env
   - Verify API key is valid
   - Check agent status in admin
   - Review agent logs

8. "Email not sending"
   Cause: Invalid RESEND_API_KEY
   Solution:
   - Verify Resend API key
   - Check email templates
   - Review Resend dashboard for errors

9. "Search not working"
   Cause: Algolia not configured
   Solution:
   - Verify Algolia credentials
   - Check products are indexed
   - Manually reindex products

10. "High response times"
    Cause: Database queries not optimized
    Solution:
    - Check database indexes
    - Enable Redis caching
    - Use connection pooling
    - Analyze slow queries

DEBUGGING TIPS:
- Check backend logs: docker logs zyloshipping-backend
- Check frontend logs: Browser console
- Test API: curl or Postman
- Check database: psql or pgAdmin
- Check Redis: redis-cli
- Monitor jobs: BullMQ dashboard

PERFORMANCE OPTIMIZATION:
- Enable Redis caching for products
- Use database indexes
- Optimize images (WebP, lazy loading)
- Enable CDN for static assets
- Use connection pooling
- Implement rate limiting

SECURITY CHECKLIST:
- HTTPS enabled
- JWT secrets strong (32+ chars)
- Database credentials rotated
- Admin password changed from default
- CORS restricted to production domains
- Rate limiting active
- Input validation enabled
- Error messages sanitized
